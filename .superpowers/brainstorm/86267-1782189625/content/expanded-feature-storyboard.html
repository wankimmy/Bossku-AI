Expanded BosskuAI feature tour

Revised to show the product beyond one task run. Target length: 78 seconds. Every feature is shown through a captured application view.

Feature coverage
01

Workspace dashboard

Actual home screen, prompt composer, navigation, and active task context. This establishes what BosskuAI looks like before the animation zooms into details.

02

Multi-agent process

Agent Process view shows the planner, executor, auditor, and final reviewer handoff around one run.

03

Plans and checklists

Plan tab shows the file-scoped execution checklist before changes begin.

04

Changes and verification

Changes tab shows files read, files changed, commands, and test activity so users can inspect what happened.

05

Approval gates

Approval Required modal shows where a risky decision pauses for a human choice.

06

Audit results

Audit panel demonstrates a second pass for findings, remaining risks, and validation status.

07

Skills and routing

Slash-command picker and Skills Graph show how focused expertise is selected instead of one generic prompt path.

08

Persistent memory

Memory inspector and project knowledge show the retained context that carries from one run to the next.

09

Model and local-first settings

Models settings show configurable roles, audit, memory, plan mode, and optional Ollama inference.

10

Works where builders work

Closing dashboard frame names the supported workspace surfaces: Cursor, Claude Code, Codex, and OpenCode.

Pacing and readability

Included

  • Two to four seconds of readable hold on each proof screen
  • One close zoom per feature, then a pull-back for context
  • Titles under eight words with large, high-contrast type
  • Emerald signals progress and amber signals human review

Deliberately excluded

  • No invented performance claims or fabricated audit outcome
  • No small dense code panes that cannot be read in a video
  • No generic marketing panels standing in for product screens
  • No abrupt cuts or overloaded text overlays

This makes the video long enough to show the product properly, while keeping each feature visually verifiable in the app.
