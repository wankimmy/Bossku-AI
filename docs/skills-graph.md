# Skills Graph

The skills graph is a focused visualization of your skill library: how skills relate to each other, which ones are high quality, which are weak, and which tend to be used together. It is a subset view of the full knowledge graph, optimized for skill management tasks.

## What the Skills Graph Shows

Unlike the full knowledge graph which includes runs, memories, files, and agents, the skills graph shows only:

- **Skill nodes** — every skill in the library (active, weak, and archived)
- **Co-occurrence edges** — connections between skills that are frequently matched together or selected in similar contexts
- **Quality overlays** — visual encoding of each skill's quality score

This narrower scope makes it much easier to spot library-level problems: duplicate skills, isolated skills that never co-occur with anything (possibly too narrow), and clusters of weak skills that suggest a domain where the library needs rethinking.

## Node Appearance

Each skill node is rendered with:

- **Color** — encodes quality tier (green/yellow/red, same scale as the knowledge graph)
- **Size** — proportional to usage count over the last 90 days; larger nodes are used more often
- **Label** — the skill name
- **`SkillQualityBadge`** — a small overlay badge showing the exact quality score and a trend arrow (improving, stable, declining)

### Using SkillQualityBadge to Identify Weak Skills

The `SkillQualityBadge` component appears on hover in the graph and on the skill list page. It shows:

- Current `quality_score` (e.g. `0.43`)
- Trend over the last 30 runs: ↑ improving, → stable, ↓ declining
- Run count (how many times this skill was used in the quality window)
- Top contributing failure reason (e.g. "3 runs with critical audit finding: SQL injection risk")

A declining badge on a previously healthy skill is an early warning. Investigate the recent runs attached to that skill before quality drops below `0.4` and the skill is auto-flagged as weak.

## Co-Occurrence Edges

An edge between two skill nodes means they were both strong candidates for the same type of request (both scored above the match threshold on the same prompt). Edge weight increases with co-occurrence frequency.

**Thick edges** between two high-quality skills suggest those domains are genuinely related in your project — consider whether a combined skill would serve users better than two separate ones.

**Edges between a high-quality and a low-quality skill** suggest the low-quality skill is often the runner-up when the high-quality one wins. This means the low-quality skill's trigger keywords overlap with the stronger skill. Review whether the weak skill is truly differentiated or should be merged.

**Isolated nodes** (skills with no co-occurrence edges) are either too narrow (only one very specific task type), recently added (not enough runs yet), or never actually matching anything. Check the skill's trigger keywords and run count.

## Graph Filters

The skills graph toolbar provides:

- **Quality filter** — show only skills above/below a quality threshold
- **Usage filter** — show only skills used at least N times
- **Status filter** — show active / weak / archived / all
- **Auto-generated filter** — show only skills generated by the learning engine (useful for reviewing the quality of auto-generated content vs. hand-written skills)

## Practical Actions from the Skills Graph

| What you see | Action |
|---|---|
| Cluster of red/yellow nodes in one domain | Open each skill, compare their trigger keywords and approaches, merge or rewrite the weakest |
| Thick edge between two weak skills | These skills compete for the same prompts; consolidate into one stronger skill |
| Large isolated node with yellow badge | High usage but mediocre quality; this skill handles a common task poorly — prioritize improvement |
| Small isolated node with red badge | Low usage, low quality; likely a stale auto-generated candidate — consider archiving |
| New green node with no edges | Newly added skill with no run history yet; check back after 10+ runs |

## Relationship to the Full Knowledge Graph

The skills graph is accessible at `/skills-graph`. The full knowledge graph is at `/knowledge-graph`. They share the same underlying `graph_nodes` and `graph_edges` data — the skills graph is a filtered view, not a separate data store.

To see a skill in context (which runs used it, which memories were involved), switch to the full knowledge graph and search for the skill by name.
