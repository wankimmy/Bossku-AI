# Self-Learning Brain

BosskuAI is designed to get measurably better with each run. The self-learning system has two input channels — automated pattern extraction and explicit user feedback — and one output: new skill candidates that, once approved, make future runs faster and higher quality.

## How Learning Happens

### Automated: LearningEngine

After every successful run, `LearningEngine` runs as a background job. It inspects the run's steps, the selected skill, the audit findings, and the final review, then extracts **patterns** — recurring combinations of intent, skill, and approach that worked well.

A pattern record contains:

- `intent_fingerprint` — a normalized embedding of the user prompt category
- `skill_used` — which skill matched
- `approach_summary` — a short description of what the executor actually did
- `run_ids` — which runs contributed to this pattern
- `occurrence_count` — how many times this pattern has been seen
- `avg_quality_score` — average audit quality across contributing runs

Patterns are stored in the `learning_patterns` table.

### Manual: FeedbackLearningService

When a user submits a thumbs-up/thumbs-down or a free-text comment on a run, `FeedbackLearningService` converts that signal into a **learning event**:

- Positive feedback increments the `positive_signal` counter on the relevant pattern
- Negative feedback with a reason generates a `feedback_correction` learning event that the Learning Inbox surfaces for review
- Free-text feedback is embedded and matched against existing patterns, then attached to the closest one

Learning events are visible in the **Learning Inbox** tab on the `/brain` page.

## The ≥3 Occurrence Threshold

A pattern becomes a **skill candidate** when `occurrence_count >= 3`. This threshold prevents one-off lucky runs from polluting the skill library. Three occurrences means:

1. The intent type has come up multiple times — it's a real recurring need
2. The same approach worked repeatedly — it's a reliable solution
3. There is enough signal to write a meaningful SKILL.md

When a pattern crosses the threshold, `LearningEngine` calls `SkillCandidateGenerator` which drafts a `SKILL.md` file. The candidate appears in the **Skill Candidates** tab on `/brain` with status `pending_review`.

## Auto-Generated SKILL.md Draft

The draft SKILL.md is generated by calling the configured planning model with:

- The pattern's intent fingerprint as a prompt description
- The top 3 run transcripts as examples
- The existing skill library as context (to avoid duplication)
- The soul.md guidelines to ensure tone consistency

The output is a complete SKILL.md with a name, description, trigger keywords, approach steps, and anti-patterns. A human must approve it before it enters the active skill index.

## Risky Categories Require Manual Review

Some skill categories are always flagged `requires_manual_review` regardless of occurrence count or quality score:

- `payment-gateway` — any skill touching payment processing
- `security` — authentication, authorization, secrets
- `deployment` — production environment changes
- `auth` — login, token, session management

For these categories the approval workflow requires an explicit admin action on the `/brain` Skill Candidates tab. They cannot be auto-approved even if the quality score is high.

## The Feedback Loop

```
Run completes
  └─► LearningEngine extracts pattern
        └─► pattern.occurrence_count >= 3?
              ├─► No  → wait for more runs
              └─► Yes → SkillCandidateGenerator drafts SKILL.md
                          └─► Human approves on /brain
                                └─► SkillIndexService activates skill
                                      └─► Next matching run uses new skill
                                            └─► LearningEngine updates quality score
```

Each loop iteration tightens the skill's approach based on real outcomes. Skills that consistently earn high audit scores have their `quality_score` raised, making them preferred by the skill matcher over lower-scoring alternatives.

## Observability

The `/brain` page gives you full visibility into the learning state:

- **Overview tab** — current learning velocity (patterns/week, candidates pending, last learning run)
- **Learning Inbox** — all unreviewed feedback learning events
- **Skill Candidates** — all draft skills awaiting approval
- **Feedback Learnings** — all converted feedback events with their matched patterns

See [`brain.md`](brain.md) for a full walkthrough of each tab.
